# Possession-proof test vectors

Machine readable copies of the signed-response possession-proof vectors we
contributed to `draft-meunier-webbotauth-httpsig-protocol`. Nothing in here is
hand written: every file is regenerated by
[`scripts/generate-directory-proof-vectors.mjs`](../scripts/generate-directory-proof-vectors.mjs)
and checked by
[`scripts/verify-directory-proof-vectors.mjs`](../scripts/verify-directory-proof-vectors.mjs),
which shares no base-construction code with the signer.

| File | Set | Served as | Authority |
| --- | --- | --- | --- |
| `directory-proof-e2-3.json` | `directory` | `application/http-message-signatures-directory+json` at `/.well-known/http-message-signatures-directory` | `signature-agent.test` |
| `jwks-uri-proof.json` | `jwks_uri` | `application/jwk-set+json` at `/tenants/acme/jwks.json` | `keys.example.net` |

Both sets use the RFC 9421 Appendix B.1.4 Ed25519 test key, so one thumbprint,
`poqkLGiymh_W0uP6PZFw-dvez3QJT5SolqXBCW38r0U`, cross-checks across both. They
serve the same key set bytes, so they carry the same `Content-Digest` and the
only line of the signature base that differs is `"@authority";req`. Neither
signature verifies for the other authority.

`directory-proof-e2-3.json` is the vector published as **-02 Appendix E.2.3**.
Its bytes are frozen: they appear in someone else's document and third parties
have reproduced them. `tests/directory-proof-vectors.test.ts` pins every
published value as a literal, so the generator cannot move them by accident.

Each file also carries two negatives, so an implementer can check that their
verifier rejects and not only that it accepts. Each negative moves exactly one
input away from the positive and reuses the positive's signature unchanged:

- `*-tampered-body`: a top-level member added to the body after signing. Fails
  on `content-digest`. The added member is ignored by every key-set parser, so
  the covered digest is the only thing that catches it.
- `*-wrong-authority`: the same response re-served under the other set's host.
  Fails on `@authority`.

## Commands

```bash
npm run build -w @ava-pay/agent   # the generator signs with the shipped SDK
npm run vectors                   # regenerate the JSON files
npm run vectors:verify            # independent verification, negatives included

# draft markdown for the appendix sections
node scripts/generate-directory-proof-vectors.mjs --set directory
node scripts/generate-directory-proof-vectors.mjs --set jwks

# check a rendered draft against the published bytes
node scripts/verify-directory-proof-vectors.mjs --from-draft draft.txt
node scripts/verify-directory-proof-vectors.mjs --from-draft draft.txt \
  --section "Signed jwks_uri response"
```
